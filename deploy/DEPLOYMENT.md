# Эксплуатация

БД, учётные данные и ключи лежат за пределами репозитория. Не отправляйте `deploy/data`, `deploy/secrets`, `.env`, первоначальный пароль администратора или старые конфиги в GitHub.

## Существующий хост

Владелец может подключить уже арендованный хост вместо заказа новой машины. Вызовите с административной сессией `POST /api/admin/adopt`, тело `{"hostId":"CHERRY_SERVER_ID"}`. Пул должен быть пустым. Сервис сначала проверяет Cherry и возможность прочитать Docker по SSH; при ошибке ничего не меняет. Конфиги старых серверов не перезаписываются; их порты обходятся при распределении. Чужие контейнеры блокируют прекращение аренды.

Ключ координатора должен уже быть разрешён в `/root/.ssh/authorized_keys` игрового хоста. Регистрация ключа в Cherry может применяться только при provisioning/rebuild; не переустанавливайте чужой работающий хост ради ключа.

`Cherry__DisableRent=true` позволяет временно запретить платные заказы во время миграции. После подключения существующего хоста его можно использовать, даже когда новые заказы запрещены.

## Сверка неопределённой операции

Администратор вызывает `POST /api/admin/recover`, тело `{}`. Для неопределённого заказа проверяется уникальный hostname через Cherry; для удаления проверяется отсутствие ID через API. Если заказ пока не найден, сервис оставляет блокировку. Только после ручного подтверждения в Cherry, что нет выполняющегося/принятого заказа, разрешён вызов с `{"confirmNoPendingCherryOrder":true}`. Он не удаляет хост и не создаёт новый, а разрешает следующий явный запуск.

Ошибочные инстансы сохраняют порты. После успешной сверки отключите такой инстанс своим аккаунтом, затем запустите его заново.

## Обновление сервиса

1. Дождитесь завершения выполняющихся операций.
2. Остановите координатор, сделайте резервную копию всей папки `data` и секретов в защищённое место.
3. Обновите исходники и соберите контейнер.
4. Поднимите сервис с прежними томами. Незавершённая очередь восстанавливается из SQLite.
5. Проверьте `/healthz`, вход и общий список серверов.

Игровые контейнеры продолжают работать, пока координатор обновляется. Резервное копирование живой БД простым `cp pool.db` без WAL запрещено; используйте SQLite backup или останавливайте сервис.

`Cherry__DisableRelease=true` запрещает прекращение аренды на время проверки. Отключение собственного Squad с `releaseIfLast=false` остаётся доступным; хост продолжает оплачиваться. На тестовом развёртывании эта блокировка включена.
